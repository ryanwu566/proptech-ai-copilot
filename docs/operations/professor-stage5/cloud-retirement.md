# Cloud Run / Render retirement gate

**NOT AUTHORIZED; no credential or service is READY_TO_RETIRE.** Both remote
control-plane credential inventories, plus Vercel and GitHub Actions scopes,
remain UNKNOWN. HTTP responses from their
public URLs do not prove configuration, use, secret presence or safe retirement.

The source dependency graph and exact Render maintenance-job dispositions are
now documented in [retirement dependency inventory](retirement-dependency-inventory.md).
Repository-read GitHub access does not include secrets-list access. Source audit
is not deployed dependency closure, and this gate is not waiting only for WAN.

Required evidence before an operator-approved retirement:

- [ ] Direct Professor inbound HTTPS trusted and functional from outside the LAN.
- [ ] Vercel Preview browser E2E PASS, followed by approved Production E2E PASS.
- [ ] Supabase identity preserved and Professor user/profile/case persistence and
  cross-user denial PASS. Supabase Auth is deliberately retained.
- [ ] ML version/support/limitations and GIS/Market/Valuation/Trend/Finder PASS.
- [ ] All four actual cloud/CI control-plane NAME inventories reconciled, including
  revisions/services/deployment scopes, CI aliases and protected secret references.
- [ ] Every required server provider credential is present under accepted
  Professor secret layout, validated/admitted separately; no unique Cloud Run/
  Render-only credential, OAuth/ADC or refresh-job dependency remains.
- [ ] Reboot acceptance including volatile credential/TLS restoration PASS.
- [ ] Logs/images/Compose contain no values, ingress/security monitoring PASS,
  quota/cost/restriction policies preserved and trusted renewal/recovery PASS.
- [ ] Protected backups and explicit Professor/Vercel rollback receipts exist;
  retirement plan independently reviewed and separately operator-approved.

Only then classify individual legacy credentials READY_TO_RETIRE. Retire
deployment-specific aliases/access independently of shared provider credentials.
Do not delete a shared Google service identity, Supabase authority, R2 archive,
CI role or cloud resource because a single runtime moved. Revoke unnecessary
old-cloud access only after final dependency audit, not by copying values into
another environment or disabling controls. No retirement command is provided.
