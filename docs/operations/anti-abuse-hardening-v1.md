# Anti-abuse hardening v1: local controls and operational acceptance

Status: executable application controls; **global production budget acceptance remains blocked** until owners verify ingress, provider quotas and spending enforcement. This change does not deploy, push, merge, change credentials, or provision infrastructure.

## Threat model and trust boundary

The legacy FastAPI map, location, terrain, satellite, valuation, Finder, Market and parcel APIs accept unauthenticated requests. CORS restricts browser access; scripts can call public APIs directly. VNext identity/planning routes require their existing authentication and feature checks. Operator Market and commute refresh routes retain token authentication. `/metrics` and `/provider-status` remain protected by the existing scrape-token contract.

Attackers can repeatedly submit valid expensive requests, vary material cache keys, consume provider quotas with failures, overwhelm category/tile workers, or send oversized/chunked geometry bodies. Local controls reject before downstream work, restrict physical concurrency and reserve bounded operation units. Successful zero Places results remain valid zero; blocked/failed categories remain missing or partial. Saved evidence is not modified by admission rejection.

`render.yaml` and `Dockerfile.cloudrun` start Uvicorn with `--no-proxy-headers`. The ASGI transport host is a **coarse direct peer**, potentially a shared ingress proxy. `X-Forwarded-For`, `X-Real-IP`, `Forwarded`, `X-Client-IP`, query parameters, correlation IDs and authentication headers never select a budget key. Missing peer identity shares `unknown`. There is no proven end-user IP trust chain and no per-user claim. Ports do not select new identities. Preserve this startup flag; a runtime command that trusts arbitrary forwarding would invalidate the boundary.

Legitimate users behind one peer share request capacity. Owners must tune thresholds against ingress aggregation before accepting production. Request admission happens before parsing: malformed requests consume the peer request budget, but never reserve provider work. Trailing slashes share the same policy, including redirects. Health/liveness/readiness and passive source/provider status are exempt from these costly request policies. `/map/google-health` reads observations/configuration and performs no active probe.

## Configuration and emergency controls

Every policy name in the table has these backend-only variables, with uppercase capability names (including `MARKET_OPS`). The executable defaults live in `services/anti_abuse.py`; names are registered in `config/hosted-environment-manifest.json`.

| Variable template | Default | Allowed behavior |
| --- | --- | --- |
| `ANTI_ABUSE_<CAPABILITY>_REQUESTS` | table peer count | positive integer, clamped to 100,000 |
| `ANTI_ABUSE_<CAPABILITY>_WINDOW_SECONDS` | table window | positive integer, clamped to 3,600 |
| `ANTI_ABUSE_<CAPABILITY>_CONCURRENCY` | table work count | positive integer, clamped to 32 |
| `ANTI_ABUSE_<CAPABILITY>_OPERATIONS` | table hourly count | positive integer, clamped to 100,000 |
| `ANTI_ABUSE_<CAPABILITY>_OPERATION_WINDOW_SECONDS` | 3,600 | positive integer, clamped to 3,600 |
| `ANTI_ABUSE_<CAPABILITY>_DISABLED` | false | true disables; malformed non-false settings fail closed |

Invalid numeric settings fail startup with a value-free configuration error. Policy changes require process replacement; changing settings does not silently recreate budgets on each request. Kill switches are read at admission and physical boundaries, and before Places/Routes/satellite cache access. In deployed environments an environment change normally requires a revision/restart; owners must change every active revision/worker. A killed satellite also prevents worker startup. The existing `EARTH_ENGINE_SATELLITE_REFERENCE_V1` enable flag and worker IAM/deadline limits remain required; no permissions are broadened.

Emergency procedure: owner sets `ANTI_ABUSE_SATELLITE_DISABLED=true`, `ANTI_ABUSE_ROUTES_DISABLED=true`, or `ANTI_ABUSE_PLACES_DISABLED=true` independently as appropriate; apply to all active revisions, and block the named routes at ingress while rollout completes. Confirm unavailable/disabled state using an owner-approved single request and aggregate metrics, not provider load tests. Already running work may finish under its existing timeout; disabling does not erase saved evidence or cancel unrelated capabilities. Preserve provider-side quotas while restarting, because restart resets local budgets. Restore one switch at a time after reviewing quota/error evidence and owner authorization. `MAINTENANCE_MODE` remains a broader existing emergency control.

## Executable resource, cache and response guarantees

- `FixedWindowRateLimiter` is reused for each capability. Atomic admission, maximum 4,096 buckets per limiter and one shared overflow bucket prevent memory growth or fresh-address overflow bypass. Expired windows are pruned; active keys are not evicted to reset their quota. The fixed set of policies bounds total state. Internal limiter failure rejects with 503.
- Each capability has a nonwaiting `BoundedSemaphore`. No provider lock serializes unrelated capabilities. Permits are released on success, exceptions and timeout; cancellation detaches an async waiter while the producer retains its permit until work stops. Synchronous transport guards run in the actual worker. Existing Earth Engine process containment and terrain/category worker pools remain intact.
- Reservations occur after completed-cache/in-flight owner selection. Hits and coalesced waiters do not spend new physical operations. Failures consume attempted work budgets, bounding repeat failure storms. Local analysis reservations are separate from downstream physical calls. Existing physical dispatch counters remain at transport/worker boundaries; TGOS and cadastral transport counters are added there. No currency costs or distributed counters are inferred.
- Places has six supported categories, a six-entry input ceiling and six default physical permits, so one ordinary full fan-out does not reject itself. Successful categories/zero results are retained; blocked categories are marked with safe reasons. All blocked categories produce a guard error instead of mock success. Other existing non-guard demo behavior is unchanged.
- Routes cache keys retain destination/mode/provider/configuration/freshness identity. Satellite remains an explicit-action POST, with no mount/reopen/Compare/Report generation, no automatic 429 retry and no new polling. A frontend request reads `detail.message`; existing request transport issues one fetch and never automatically retries.
- Write bodies are counted before parsing, including absent/false `Content-Length`: 1,000,000 bytes normally; 11,000,000 bytes for multipart parcel uploads, preserving the 10 MiB file contract. There are 16 nonwaiting write-body slots per process and a 15-second body-receive deadline. Slots are held through request completion; capacity rejection is 503. GET/HEAD/OPTIONS do not parse bodies or occupy these slots, keeping health independent. Query strings are capped at 8,192 bytes.
- Public provider-query DTO strings are at most 512 characters, coordinates finite and range checked, radii remain 100–5,000m for Places / 100–1,500m Location / 100–2,000m terrain. Layer lists are at most 16, Finder districts at most 30, Trend horizons at most 12. Existing Finder/comparable result ceilings remain 100/10. Geometry is cumulatively bounded at 100,000 coordinates before native construction/union across GeoJSON, KML and Shapefile. Existing 1,000-feature, 100-archive-file, 50 MiB expanded-archive and compression-ratio limits remain. Upload parsing/GEOS runs in a bounded parcel worker thread rather than blocking the event loop. Existing provider timeouts, image/tile/cache byte ceilings remain.
- 429 identifies request/operation budget exhaustion with integer `Retry-After`; 503 identifies disabled/busy/unavailable capability. Invalid/oversized input uses 400/413/422, query overflow 414, receive timeout 408. Responses contain bounded categorical reasons and safe correlation IDs, never peer keys, credentials, raw providers or stack traces. VNext guard responses preserve 429/503 and disable automatic-retry advice. CORS surrounds new admission responses so the authorized frontend can read their messages/Retry-After.
- The protected existing metrics endpoint emits fixed capability/event counters for admissions, rejects, rate/capacity/kill/budget failures, reservations, physical calls, cache hits/misses/coalescing and provider failures/timeouts. No addresses, exact coordinates, peers or user IDs enter metric labels. Nested terrain failures retain error/limited evidence; some existing subprovider envelopes retain their generic failure reason.

## Owner contract: global production acceptance blockers

Per-process controls reset on cold start and do not coordinate workers, revisions, instances, regions, credential consumers, or scripts. Two independent `AbuseControls` objects demonstrably each admit their own budgets. No Redis/shared production infrastructure was added. Max instances alone is not a mathematical global spending ceiling, and restarts/revision overlap can multiply local budgets.

Before accepting production, named service, security and billing owners must record a redacted acceptance record containing the following concrete items. No recipient identities, quota values, cloud-resource identities or money amounts are invented by this change.

1. **Ingress owner:** record deployed platform, project/service/revision identities, worker count, ingress paths and runtime command. Confirm `--no-proxy-headers`; either accept coarse-peer behavior with measured legitimate usage or separately prove a trusted forwarding chain with stripped attacker headers, exact trusted proxy ranges and direct-origin exclusion. Configure capability-specific edge aggregate and client throttles/WAF, matching the actual routes above. On Cloud Run, attach an approved load balancer/Cloud Armor policy and prevent default-origin bypass using the documented ingress/default URL controls. On Render/Vercel, verify the actual plan's supported edge controls and all direct backend access paths; do not assume frontend protection covers the backend. [Cloud Armor integration](https://docs.cloud.google.com/armor/docs/integrating-cloud-armor), [rate limiting](https://docs.cloud.google.com/armor/docs/rate-limiting-overview).
2. **Provider owner:** record the Google project(s), enabled APIs, quota metrics, effective limits and all credentials/consumers sharing them. Set deliberately reduced enforceable Geocoding, Places Nearby and Routes computeRoutes quotas using available project quota controls; capture confirmation and resulting limits. No unsupported daily quota or per-call price is assumed. Restrict server credentials to approved APIs and deployed server origins/IPs where appropriate; browser Maps restrictions are a separate owner contract. [Maps quota/usage guidance](https://developers.google.com/maps/faq), [usage and monitoring](https://developers.google.com/maps/reporting-and-monitoring/reporting).
3. **Earth Engine owner:** retain existing ADC/IAM scope, verify project concurrent request and daily EECU-time controls (`earthengine.googleapis.com/daily_eecu_usage_time`) and accepted feature access. Record observed quota enforcement, not just configuration presence. Satellite generation remains one app operation unit comprising SDK generation/download stages, not an estimate of EECU consumption. [Earth Engine quotas](https://developers.google.com/earth-engine/guides/usage), [cost controls](https://developers.google.com/earth-engine/guides/cost_controls).
4. **Billing owner:** choose approved financial targets and configure actual/forecast alerts at owner-approved thresholds (proposed 50/80/100%). Record explicit primary/backup alert recipient addresses, delivery confirmation, incident escalation and response SLA. Alert-only budgets do not cap usage/spending. If eligible spend caps are used, verify the exact supported services, project/account eligibility, reporting/enforcement delay and outage consequences; do not infer Maps/GEE coverage from a Cloud Run cap. Pair alerts with enforced provider quotas and an owner-approved capability shutoff procedure. [Budgets and alerts](https://docs.cloud.google.com/billing/docs/how-to/budgets), [spend-cap scope](https://docs.cloud.google.com/billing/docs/how-to/budgets-spend-caps).
5. **Reliability owner:** set recorded Cloud Run/hosted instance and request concurrency ceilings appropriate to memory/CPU, accounts for max 16 body buffers and native geometry workers, and validates autoscaling/revision overlap. Record a maximum exposure model across all credential consumers plus rollback/restart behavior. [Cloud Run max instances](https://docs.cloud.google.com/run/docs/configuring/max-instances), [request concurrency](https://docs.cloud.google.com/run/docs/about-concurrency).

## Rollout, rollback and safe verification

Local verification only for this implementation: `python -m pytest -q tests/test_anti_abuse.py tests/test_rate_limit.py tests/test_google_provider_cost_optimization.py tests/test_provider_request_cache.py tests/test_satellite_cost_optimization.py tests/test_terrain_provider_cost.py tests/test_api_cost_journey.py`. Fixtures use fake clocks, transport mocks, blocked-thread events and deterministic async cancellation. The full Python suite and mocked frontend/browser regressions verify evidence, cache and cost contracts. Never run abuse tests against a hosted backend/provider. The local production smoke is provider-free; hosted quota verification is a separate explicitly approved owner action.

After owner review, stage disabled high-cost features in a canary with quotas/edge rules already active. Compare legitimate admissions, latency, capability rejects, reservations, physical calls, cache hits and failures. Prove shared-proxy users can perform one normal workflow, six Places categories remain complete when available, and unhealthy providers preserve unrelated saved evidence. Enable one capability at a time. Capture redacted provider/edge evidence and owner signoff before claiming production acceptance.

Rollback keeps edge/provider quotas and emergency disable switches active while reverting the application revision. Remove canary traffic and drain/retires old workers; confirm deployed identity/version and protected passive health. Do not restart to evade an exhausted local budget. Do not lift global quotas or widen IAM as a rollback shortcut. Missing owner values, alert recipients, provider enforcement evidence or direct-origin controls remain explicit acceptance blockers.
